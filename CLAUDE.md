# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Current state

Phases 0 (foundation and risk spikes), 1 (CI/CD), 2 (app skeleton and design system), 3 (job queue and upload) and 4 (file transcription, in six stages 4.1–4.6 listed in `ROADMAP.md`) are done. Phase 5 ("Guardar áudio") is in progress, in two stages with their own PRs: 5.1 `media::encode_audio` (the AAC `.m4a` encoder, not yet used by the app) and 5.2 the "Guardar o áudio?" flow in the app. The app transcribes uploads on the dedicated GPU (large-v3-turbo) or the CPU (`small`), in ~30-min blocks so 2–3 h meetings stay under ~1.5 GB of RAM (measured: 1 h in 2 min 9 s on the RTX 3050 and 8 min on the CPU), and the CI release (v0.2.0, tagged only with the user's ok) embeds the `small` and transcribes on the CPU. The product flow is automatic: receive or record → extract audio → transcribe to `.txt` and `.md` → ask "Guardar o áudio?" (discard the temp media, or encode an AAC `.m4a` saved where the user picks in the Windows "Save as" dialog). Media is disposable: video compression was dropped; Phase 5 is "Guardar áudio" and recording Phase 6. The repo is `filipimr/scriba` (public) with `main` protected (checks `checks` and `deny` required); `README.md` (pt-BR) presents it on GitHub. The `scriba` binary serves the UI:

- `src/app.rs`: single instance and the server + worker lifecycle.
- `src/web/`: Axum router, `security.rs` (token/Host/Origin guard), embedded `assets.rs`, askama `pages.rs`, `reader.rs` (the result of a done job: the reader `GET /jobs/{id}` from the `.txt` on disk via `transcript::parse`, 404 page for an id not in the list; `GET /api/jobs/{id}/transcricao.{txt,md}` as attachments with a UTF-8 `filename*`; `POST /api/jobs/{id}/open`, 204, through `state.opener`), and `jobs.rs` (streaming multipart upload to `<data-dir>/uploads`, then the pipeline's probe in `spawn_blocking` (422 with the friendly message for no audio / not media); the `/api/jobs` routes answer HTML fragments, 286 stops the 1 s polling of a card; `POST /api/jobs/{id}/retry`; `DELETE /api/jobs/{id}` of a done job needs `?confirm=1`, else 409, and sends its folder to the Recycle Bin).
- `src/jobs/`: the in-memory queue. `model.rs` holds the pure state machine (queued, running, done, failed, canceled; `Retry` takes failed back to queued); `id.rs` a hand-rolled ULID; `store.rs` the `Jobs` handle (it owns the pipeline, for the probe and the footer; a failed job keeps its upload for the retry); `worker.rs` the dedicated thread (one job at a time, `catch_unwind`, cooperative cancel via `AtomicBool`); `pipeline.rs` the `Pipeline` trait (`probe`, `backend`, `run`).
- `src/engine.rs`: `Engine`, the app's pipeline: `media::extract_audio_into` a `Spool` (`uploads/<id>.f32`, next to the upload) → `asr::transcribe_samples` block by block → `transcript::write`, with GPU detection at creation (synchronous). The spool is deleted on any outcome; `uploads/` is emptied at startup. `write_outputs` builds the header and the `job.json`.
- `src/jobs/fake.rs`: `FakePipeline`, only with `cfg(test)` or the `test-support` feature (`--fake-pipeline` runs the app with it). It never reads the file and writes a fixed transcript with the real `transcript`. File names steer it: `lento` (10× slower), `falha` (friendly failure), `falha-uma-vez` (fails only the first try), `panico` (panic) and `sem-audio` (the probe rejects it).
- `src/trash.rs`: the Windows Recycle Bin (`SHFileOperationW` with `FOF_ALLOWUNDO`).
- `src/opener.rs`: the `Opener` trait behind "Abrir pasta". `SystemOpener` uses `open::that_detached`; `PrintOpener` (`cfg(test)` or `test-support`, picked by `--fake-pipeline`) only prints `abrir pasta: <dir>` to stdout, which the E2E fixture exposes as `scriba.opened()`.
- `src/media/`: `probe` (duration, bit rate, resolution, audio/video present) and `extract_audio`/`extract_audio_into` (best audio track → 16 kHz mono f32, no video decoding, progress by pts, cancel checked per packet; `_into` hands the samples to a sink, `Error::Disk` if it fails), both through the private `Source` (open + decode to a given rate). `encode_audio` (Phase 5) re-encodes the original's best audio track to an AAC-LC mono `.m4a` (muxer `ipod`, `+faststart`) at 64 kbps and `audio_rate` (the original's rate if AAC allows it, capped at 32 kHz, never upsampled), with progress and cancel; on any error it deletes the partial output (`Error::Encode` for write failures). `spool.rs` is the extracted audio on disk (raw f32 LE), read back by range. `media::Error` carries the friendly pt-BR messages and converts into `jobs::Failure`; technical detail goes to stderr.
- `src/transcript/`: segments → paragraphs (a pause > 1.5 s breaks), `render_txt` (UTF-8, CRLF) and its inverse `parse` for the reader, `render_md` (escaped Markdown). `output.rs` holds the folder name `AAAA-MM-DD HHmm - nome` (`clean_name` for Windows, " (2)" on collision), atomic writes, and the `job.json` manifest v1; `write` removes the folder if anything fails.
- `src/asr/`: transcription. `backend.rs` reads the ggml device registry (`devices()`, via whisper-rs `raw-api`) and the pure `plans()` (dedicated GPUs by memory → CPU with `small`; the integrated GPU is left out, slower than the CPU in the 4.3 benchmark; a candidate needs its model); a GPU candidate is checked through the whisper.cpp log (`log.rs`), since a failed GPU silently falls back to CPU. `vad.rs` runs Silero itself (whisper-rs `state.full` ignores `params.vad`), loaded from memory, splices the speech and maps times back (`TimeMap::offset` adds the block start). Long audio goes in blocks of ~30 min (`Asr::blocks` changes the size; tests use seconds): the `Samples` trait reads each window (from a slice or the `Spool`), the VAD runs on it and `blocks.rs` cuts in the middle of the longest pause in its last sixth (else the last pause in the window, else a hard cut), so RAM follows the block, not the duration, and paragraphs at the seam break as in the original. `cache.rs` is `IdleCache` (unload after 10 min idle), `phantom.rs` the hallucination filter, `models.rs` embedded or `models/` models. Progress and abort use our own C trampolines (whisper-rs 0.16's "safe" ones leak, and the abort one is type-confused).
- `src/clock.rs`: local time via `GetLocalTime`/`GetSystemTime`, with the UTC offset from their difference.
- `src/config.rs` (paths, `config.json`), `src/instance.rs` (`instance.json`) and `--self-test` in `src/self_test.rs`.

Templates live in `templates/`, CSS source in `ui/`, embedded files in `assets/`. Other crates: `crates/scriba-model` (models embedded via `include_bytes!`: `embedded-cpu-model` = the `small` CPU model + Silero VAD + `fala.wav`, the CI release; `embedded-model` = that plus large-v3-turbo), `crates/spikes` (the Phase 0 spikes as tests), and `xtask`. The app transcribes uploaded files and shows the result (reader, Copy, Download, Open folder; `assets/app.js` holds the toast, the clipboard copy from a `<template>` and the fetch-based downloads) and has no recording. Document new commands here as each phase adds them.

## Environment and commands

- One-time setup, in an admin PowerShell: `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1`. It is idempotent; `-LimparVcpkg` deletes vcpkg temp files. It installs the toolchain and sets the user variables `VCPKG_ROOT=C:\dev\vcpkg`, `LIBCLANG_PATH`, and `CARGO_TARGET_DIR=C:\dev\t\scriba`. The short target dir is required: inside the repo, the whisper.cpp Vulkan build exceeds MAX_PATH.
- Static FFmpeg (once, then cached): `C:\dev\vcpkg\vcpkg.exe install --triplet x64-windows-static-release --x-install-root=vcpkg_installed`. The triplet is the release-only overlay in `triplets/` (declared in `vcpkg.json`); debug libs were never linked. In manifest mode, installing another triplet replaces `vcpkg_installed/`, so an environment from before Phase 3.5 reinstalls FFmpeg once with this command.
- `.cargo/config.toml` holds the build env: triplet `x64-windows-static-release`, `+crt-static`, `FFMPEG_DIR`, the whisper.cpp `GGML_*` SIMD baseline, `CMAKE_MSVC_RUNTIME_LIBRARY`, and `CMAKE_{C,CXX}_FLAGS_RELEASE`. Without those last two, the release build of whisper.cpp comes out unoptimized (`/Od`): cmake-rs strips `/O*` and overwrites the Release flags under the Visual Studio generator. Changing `GGML_*`/`CMAKE_*` needs `cargo clean -p whisper-rs-sys` (plus `--release` for the release profile), because the build script does not track them; `release.yml` does this clean before building.
- `cargo xtask model` downloads the models to `models/` and checks SHA-256; `--only` takes comma-separated name fragments (`--only base` is what CI uses; `--only small` fetches the CPU-model candidate). `cargo xtask fixtures` regenerates `tests/fixtures/`; `--only` takes comma-separated file names (e.g. `--only fala.mkv,pausas.wav`) and reuses the existing `fala.wav`, so new fixtures never change the current ones. It needs the "Microsoft Maria" SAPI voice and the `ffmpeg` CLI.
- Lint: `cargo fmt --all --check` and `cargo clippy --workspace --all-targets --features "spikes/vulkan scriba/test-support" -- -D warnings`.
- Tests: `cargo nextest run --workspace --features "spikes/vulkan scriba/test-support"` (`tests/upload.rs` has `required-features = ["test-support"]`). Prefer nextest over `cargo test` for the whole workspace: it runs the whisper binaries one test at a time (`.config/nextest.toml`), while `cargo test` runs a binary's whisper tests in parallel and their busy-waiting threads can stall for tens of minutes; with `cargo test`, pass `-- --test-threads=1` to those binaries. Hardware tests (GPU, NVENC, real audio devices, large model) are `#[ignore = "hardware"]`; run them locally with `cargo test -p spikes --features vulkan -- --ignored`. Measure whisper speed in `--release`, on AC power and in best-performance mode (on battery the CPU numbers drop sharply).
- App transcription (`asr`) tests: `cargo test --test asr` (base + Silero on CPU, what CI runs; needs `cargo xtask model --only base,silero`). Hardware: `cargo test --release --features vulkan --test asr -- --ignored`. The whole pipeline through the real queue: `cargo test --test engine` (same models); on the GPU, `cargo test --release --features vulkan --test engine -- --ignored --test-threads=1 --nocapture`. Its `uma_hora`/`tres_horas` need `SCRIBA_LONG_AUDIO`/`SCRIBA_LONG_AUDIO_3H` (long media), measure time and peak RAM (≤ 1.5 GB) per backend (`SCRIBA_LONG_DEVICES=gpu,cpu`; `SCRIBA_LONG_BLOCK_MIN` overrides the block) and leave the transcripts in `%TEMP%\scriba-longo`; one test per process (`--test-threads=1`), because the RAM sampler measures the whole process. `cargo run --features vulkan` builds the app with Vulkan.
- App benchmark small × base × large (hardware): `cargo test --release --features vulkan --test bench_asr -- --ignored --nocapture`, steered by `SCRIBA_BENCH_MODELS`, `SCRIBA_BENCH_DEVICES` (`cpu,igpu,gpu`), `SCRIBA_BENCH_AUDIO` (media files; reference text from `<name>.ref.txt`, else large on the dedicated GPU) and `SCRIBA_BENCH_BEAM`; prints WER, RTF, load and RAM tables.
- Transcription benchmark (hardware): `cargo test -p spikes --release --features vulkan --test bench -- --ignored --nocapture`, steered by `SCRIBA_BENCH_MODELS` (`base,small,large`), `SCRIBA_BENCH_DEVICES` (`cpu` and Vulkan indices), `SCRIBA_BENCH_FLASH` (`0,1`), `SCRIBA_BENCH_THREADS`, `SCRIBA_BENCH_AUDIO` (16 kHz mono WAV) and `SCRIBA_BENCH_REPEAT`; it prints a Markdown table.
- `--self-test` also prints `whisper_print_system_info()`, and fails if transcription exceeds `SCRIBA_SELF_TEST_MAX_SECS` (set only by `release.yml`, as a guard against an unoptimized whisper.cpp).
- Upload memory: `tests/upload.rs` streams `SCRIBA_UPLOAD_MB` megabytes (default 256, what CI runs) through the real exe (with `--fake-pipeline`) and checks its peak working set. The Phase 3 criterion is `SCRIBA_UPLOAD_MB=2048 cargo test --features test-support --test upload -- --nocapture`.
- Text snapshots of the `.txt`/`.md` live in `src/transcript/snapshots/` (accept with `INSTA_UPDATE=always cargo test --lib transcript`). `tests/media.rs` runs `media` against every fixture format; its `guardar_audio_longo` (ignored) encodes `SCRIBA_LONG_AUDIO` and prints time and size (`cargo test --release --test media -- --ignored --nocapture`, output in `%TEMP%\scriba-longo`).
- HTML snapshots (`insta`) of the job card and the reader live in `src/web/snapshots/`. After an intended markup change, accept them with `INSTA_UPDATE=always cargo test --lib web::` and review the diff.
- The FFmpeg cache key is the triplet plus the hash of `vcpkg.json` and `triplets/`. Changing either costs one cold FFmpeg build on the branch and another on `main` (`main` does not read caches saved by PRs). CI also runs weekly on `main` (`schedule`, or `gh workflow run ci.yml`) so the caches never sit 7 days unused, when GitHub evicts them.
- CI runs `cargo llvm-cov nextest --workspace --profile ci` (nextest config in `.config/nextest.toml` serializes whisper tests) and `cargo deny check` (`deny.toml`). CI has no Vulkan, so clippy there runs without `spikes/vulkan`.
- `scriba --self-test` transcribes a sample on CPU through `media` and `asr` and encodes a short x264 clip. Release builds use `cargo build --release --features embedded-cpu-model` (embeds `ggml-small-q5_1.bin`, the Silero VAD and `tests/fixtures/fala.wav`; needs `cargo xtask model --only small,silero`), which is also the model the app uses on the CPU; without the feature it reads from `models/` (`small`, else `base`).
- Releases: push a tag `vX.Y.Z` matching the `scriba` version in `Cargo.toml`; `.github/workflows/release.yml` builds, smoke-tests, and publishes exe + SHA-256 + `THIRD_PARTY_LICENSES.html` (`cargo about`). Without a tag (PRs touching the release files, or `gh workflow run release.yml --ref <branch>` once the trigger is on `main`) it builds and smoke-tests without publishing. The `setup-native` action takes `models:` (the `--only` list; `base,silero` by default, `small,silero` in the release).
- Run the app: `cargo run` opens the browser on `http://127.0.0.1:47800/?t=<token>` (the token becomes an `HttpOnly; SameSite=Strict` cookie). Flags: `--no-open`, `--port` (falls back to a free port if busy; `0` = any), `--data-dir` (default `%LOCALAPPDATA%\Scriba`), `--output-dir` (default `Documentos\Scriba`), and `--fake-pipeline` (only with the `test-support` feature). A second run finds the live instance via `<data-dir>/instance.json` + `/health`, prints its URL and exits. Ctrl+C shuts down cleanly.
- CSS: `cargo xtask css` regenerates `ui/tokens.css` from the `DESIGN-scriba.md` YAML (fails if any component text/background pair is below WCAG AA) and compiles `assets/app.css` with the pinned Tailwind CLI (downloaded to `$CARGO_TARGET_DIR/tools`). Both outputs are committed; run it after changing tokens, `ui/app.css` or template classes. CI runs `cargo xtask css --check`.
- E2E: `cargo build --features test-support && cd e2e && npm ci && npx playwright test`. The `scriba` fixture in `e2e/fixtures.ts` starts a fresh debug `scriba.exe --fake-pipeline` per test (from `CARGO_TARGET_DIR`, or `SCRIBA_EXE`; port 0, temp data dir, `outputDir` exposed), driven in the installed Edge (`channel: "msedge"`). Visual comparisons run only in CI; references live in `e2e/tests/*-snapshots/` and are regenerated by the manual `e2e-snapshots.yml` workflow (`gh workflow run e2e-snapshots.yml --ref <branch>`, then download the artifact and commit it).
- Spike D binary: `cargo build --release -p spikes --features "vulkan embedded-model" --bin exe_unico` (since 4.6 `embedded-model` also embeds the `small`, ~190 MB more).

## How work proceeds

- One phase at a time. Start a phase only when the user asks, with its own detailed plan approved before execution, and do not roll into the next phase when it finishes.
- When a phase starts, set its row in the `ROADMAP.md` status table to "Em andamento". When it finishes, tick its checklists, set it to "Concluída", and record decisions and measured numbers in "Registro de decisões".
- A feature is done only when it has automated tests at the right level (see "Qualidade e testes" in `ROADMAP.md`) and CI is green. Tests that need real audio devices or a GPU belong in the local hardware suite, not in CI.
- If a spike or test invalidates a decision, update `ROADMAP.md` before continuing.

## Design system (`DESIGN-scriba.md`)

`DESIGN-scriba.md` is a DESIGN.md-style document in two parts:

- **YAML front matter** holds the design tokens, with English keys: `colors`, `typography`, `rounded`, `spacing`, `motion`, `elevation`, and `components`. Components reference tokens with `{group.token}` syntax, e.g. `backgroundColor: "{colors.primary}"`, and variants are separate keys (`button-primary-active`, `record-button-recording`). Phase 2 turns these tokens into CSS via `cargo xtask css`.
- **Markdown body** (pt-BR) explains the system: brand and logo, iconography, colors, typography, layout, elevation, shapes, motion, components, accessibility, microcopy, do's and don'ts, iteration guide, and known gaps.

It is the Scriba app's own design system, inspired by Apple's visual language: one blue accent for actions, pills, Inter with negative tracking, and a monochrome brand. The source logo is `docs/brand/logo-original.jpg`.

## Editing `DESIGN-scriba.md`

- Keep the front matter and the prose in sync. A token or component changed in YAML must be reflected in the body sections that describe it, and vice versa.
- Reference tokens with `{...}` rather than raw hex values in components. The body repeats hex values for readability; keep those matching the YAML.
- Follow the rules the spec sets:
  - `colors.primary` is the only action color; status colors mark state, never actions (sole exception: `button-danger` inside `confirm-dialog`).
  - Weight ladder 400/600.
  - Body text at 17px.
  - No gradients; shadows only on `toast` and `confirm-dialog`.
  - All text meets WCAG AA contrast in both themes.
  - Light and dark themes: `colors:` is the light theme, `themes.dark` overrides only differing colors. Every new color needs a dark value. Blue text uses `colors.link`; `colors.primary` is only for fills.
- Document default, pressed, focus, disabled, and error states, not hover.
- Preserve the "Lacunas conhecidas" section and update it when a gap is filled rather than deleting it silently.
