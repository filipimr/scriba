# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Current state

Phases 0 (foundation and risk spikes), 1 (CI/CD), 2 (app skeleton and design system), 3 (job queue and upload), 4 (file transcription, in six stages 4.1–4.6 listed in `ROADMAP.md`) and 5 ("Guardar áudio", in stages 5.1 encoder and 5.2 app flow) and 6 (live recording, in stages 6.1 capture and `Recorder` (`src/capture/`), 6.2 recording job and labeled transcript, 6.3 UI and routes (`src/web/record.rs`) and 6.4 the hardware "Pronto quando" with the release exe) are done. Phase 7 (tray app, logs, packaging) starts only when asked. The app transcribes uploads on the dedicated GPU (large-v3-turbo) or the CPU (`small`), in ~30-min blocks so 2–3 h meetings stay under ~1.5 GB of RAM (measured: 1 h in 2 min 9 s on the RTX 3050 and 8 min on the CPU), and the CI release (v0.2.0, tagged only with the user's ok) embeds the `small` and transcribes on the CPU. The product flow is automatic: receive or record → extract audio → transcribe to `.txt` and `.md` → ask "Guardar o áudio?" on the done card (discard the upload kept in `uploads/`, or encode an AAC `.m4a` saved where the user picks in the Windows "Save as" dialog). Media is disposable: video compression was dropped, and the upload waits for the answer only until the job is removed or the app closes. The repo is `filipimr/scriba` (public) with `main` protected (checks `checks` and `deny` required); `README.md` (pt-BR) presents it on GitHub. The `scriba` binary serves the UI:

- `src/app.rs`: single instance and the server + worker + `Recorder` lifecycle; at startup `resume_recordings` puts every recording `capture::recover` finds in `<data-dir>/gravacoes` (`Paths::recordings_dir`) back in the queue; the `Recorder` (`CpalSource`, or the `ScriptedSource` with `--fake-audio`) hands each finished recording to `Jobs::submit_recording` (`on_finish`); on Ctrl+C, `AppState::close` ends the levels SSE, and after the server stops `recorder.finish_on_exit()` closes the WAVs before `worker.shutdown` (the recording comes back next start).
- `src/web/`: Axum router, `AppState` (`Desktop` groups the opener, the save dialog and the `Recorder`), `security.rs` (token/Host/Origin guard), embedded `assets.rs`, askama `pages.rs` (pages are `Cache-Control: no-store`, so Back shows the current list; `Layout.bar` is the `recording-bar` rendered on every page), `reader.rs` (the result of a done job: the reader `GET /jobs/{id}` from the `.txt` on disk via `transcript::parse`, 404 page for an id not in the list; `GET /api/jobs/{id}/transcricao.{txt,md}` as attachments with a UTF-8 `filename*` (`download_base`: the original name, or the output folder's for a recording, whose list name has `/` and `:`); `POST /api/jobs/{id}/open`, 204, through `state.opener`), and `jobs.rs` (streaming multipart upload to `<data-dir>/uploads`, then the pipeline's probe in `spawn_blocking` (422 with the friendly message for no audio / not media); the `/api/jobs` routes answer HTML fragments, 286 stops the 1 s polling of a card; `POST /api/jobs/{id}/retry`; `DELETE /api/jobs/{id}` of a done job needs `?confirm=1`, else 409, and sends its folder to the Recycle Bin; 409 while its audio is being saved), and `audio.rs` ("Guardar o áudio?": `POST /api/jobs/{id}/audio/{discard,save,cancel,show}`; `save` answers at once with the card in "Escolhendo onde guardar…" and the card polls `GET /api/jobs/{id}?audio=1`, whose final 286 announces "Áudio de X guardado." or carries the error as `HX-Trigger: {"scriba-erro": …}` (JSON escaped to ASCII, shown as a toast by `app.js`); the dialog opens in the last chosen folder (`config.json` `audio_dir`) unless it was another transcript's folder, else this transcript's folder, with the name `<transcript folder>.m4a`), and `record.rs` (live recording: `POST /api/record/{start,stop}` answer out-of-band fragments (`hx-swap="none"`): the `recording-bar` and, with `?painel=1` (the home page), the `record-panel` and, on stop, the new card `afterbegin:#jobs`, plus the `#avisos` notice; start: 409 busy, 507 disk/files, 422 no mic/output or mic blocked, shown in the panel (`alert-inline`) or, without the panel, as a `scriba-erro` toast; the bar is the only poller: `GET /api/record/status?id=<rec>[&painel=1]` answers the bar plus only the panel's timer and alerts while recording (so the open Ajustes stay open), and 286 when idle, with the card and the `End::message` toast if `<rec>` ended; `app.js` drops a duplicated card; `GET /api/record/levels` is the SSE (every 100 ms `{"tempo","niveis"}`, meter scale −60..0 dBFS, ends with `event: fim` on stop or `AppState::close`); `GET/POST /api/record/devices` are the Ajustes (`config.json` `mic`/`output`, empty = Windows default; a saved id that vanished falls back to the default; 409 while recording; Bluetooth warning for the chosen or default mic)).
- `src/jobs/`: the in-memory queue. `model.rs` holds the pure state machine (queued, running, done, failed, canceled; `Retry` takes failed back to queued; `Done` carries `Audio`, the "Guardar o áudio?" machine: pending → choosing → saving → saved, or discarded; cancel or error goes back to pending; `Media` is video, audio or `Recording`, whose `Job.input` is the recording folder; `Job::recording` names it "Gravação de 20/10, 14:30" with `RECORDING_COST` (2.2×, measured in 6.4) times a file's estimate); `id.rs` a hand-rolled ULID; `store.rs` the `Jobs` handle (it owns the pipeline, for the probe, the estimate and the footer; `submit_recording`; a failed job keeps its media for the retry and a done one until the audio answer; discard, save, remove and cancel delete the media by kind, the upload file or the whole recording folder; a finished recording is marked `transcrita` in its `gravacao.json`; `save_audio` runs the dialog and the encode on its own thread per job, writing `<file>.parte` and renaming it); `worker.rs` the dedicated thread (one job at a time, `catch_unwind`, cooperative cancel via `AtomicBool`; `shutdown` also cancels audio saves, empties `uploads/` and deletes only the transcribed recordings awaiting the answer, so a queued, running (the Ctrl+C cancel keeps its folder) or failed one comes back next start); `pipeline.rs` the `Pipeline` trait (`probe`, `backend`, `estimate` (default `None`), `run`, `save_audio`).
- `src/engine.rs`: `Engine`, the app's pipeline: `media::extract_audio_into` a `Spool` (`uploads/<id>.f32`, next to the upload) → `asr::transcribe_samples` block by block → `transcript::write`, with GPU detection at creation (synchronous). The spool is deleted on any outcome; `uploads/` is emptied at startup. A recording extracts `sistema.wav` ("Outros") then `mic.wav` ("Você"), each to its own spool inside the recording folder, then transcribes both (each track takes half of each stage's progress, so the card never goes back a stage; a track with no samples is skipped), merges them with `transcript::merge` and saves with the speakers; its "Guardar áudio" is `media::encode_mix` of the two tracks. `write_outputs` builds the header and the `job.json`.
- `src/jobs/fake.rs`: `FakePipeline`, only with `cfg(test)` or the `test-support` feature (`--fake-pipeline` runs the app with it). It never reads the file and writes a fixed transcript with the real `transcript`. File names steer it: `lento` (10× slower), `falha` (friendly failure), `falha-uma-vez` (fails only the first try), `panico` (panic), `sem-audio` (the probe rejects it), `audio-ruim` ("Guardar áudio" fails) and `audio-demorado` (only the save is 10× slower). A recording gets a fixed transcript labeled "Você"/"Outros". Its `save_audio` writes a fixed text instead of an `.m4a`.
- `src/trash.rs`: the Windows Recycle Bin (`SHFileOperationW` with `FOF_ALLOWUNDO`).
- `src/opener.rs`: the `Opener` trait behind "Abrir pasta" (`open`) and "Mostrar no Explorer" (`reveal`, the file selected via `SHOpenFolderAndSelectItems`). `SystemOpener` uses `open::that_detached` and the shell; `PrintOpener` (`cfg(test)` or `test-support`, picked by `--fake-pipeline`) only prints `abrir pasta: <dir>` / `mostrar arquivo: <file>` to stdout, which the E2E fixture exposes as `scriba.opened()` / `scriba.revealed()`.
- `src/dialog.rs`: the `SaveDialog` trait behind "Guardar áudio". `SystemDialog` is the Windows `IFileSaveDialog` (crate `windows` 0.62) on its own STA thread, owned by a hidden topmost window centered on the browser's monitor, with the `AttachThreadInput` + `SetForegroundWindow` trick so it opens in front of the browser; cancel is `Ok(None)`. `ScriptedDialog` (`test-support`, `--fake-pipeline`) prints `salvar como: <dir>|<name>` and answers with the content of `<data-dir>/salvar-como.txt` (empty or missing = cancel); the E2E sets it with `scriba.saveAs()` and reads `scriba.asked()`.
- `src/media/`: `probe` (duration, bit rate, resolution, audio/video present) and `extract_audio`/`extract_audio_into` (best audio track → 16 kHz mono f32, no video decoding, progress by pts, cancel checked per packet; `_into` hands the samples to a sink, `Error::Disk` if it fails), both through the private `Source` (open + decode to a given rate). `encode_audio` (Phase 5) re-encodes the original's best audio track to an AAC-LC mono `.m4a` (muxer `ipod`, `+faststart`) at 64 kbps and `audio_rate` (the original's rate if AAC allows it, capped at 32 kHz, never upsampled), with progress and cancel; on any error it deletes the partial output (`Error::Encode` for write failures). `encode_mix` (Phase 6) reads a recording's WAVs with `hound` (mono 16-bit, same rate), sums them in 1 s blocks clamped to ±1 (the shorter track padded with silence) and feeds the same `AacWriter`, with no mixed file on disk. `spool.rs` is the extracted audio on disk (raw f32 LE), read back by range. `media::Error` carries the friendly pt-BR messages and converts into `jobs::Failure`; technical detail goes to stderr.
- `src/transcript/`: segments → paragraphs (a pause > 1.5 s or a speaker change breaks), `render_txt` (UTF-8, CRLF) and its inverse `parse` for the reader, `render_md` (escaped Markdown). A recording (`Header.recording`) has `Gravação: Você (microfone) e Outros (som do PC)` instead of `Arquivo:` and `[hh:mm:ss] Você: …` paragraphs (`**[hh:mm:ss] Você:**` in the `.md`); `parse` reads the `Speaker` only under that header, so an upload never gets a label. `merge.rs` merges the two tracks by time and drops the echo: a "Você" segment is echo when an "Outros" segment crosses its ±1 s window and ≥ 60% of its words (lowercase, no punctuation or accents) appear in order (LCS) in that window's "Outros" text; a long "Você" (≥ 8 words) is also echo when ≥ 60% of it is in one "Outros" segment from the last 10 min, or in the "Você" text of the 30 s before its end (the whisper loop on raw echo); "Outros" never changes. `output.rs` holds the folder name `AAAA-MM-DD HHmm - nome` (`- Gravação` for a recording; `clean_name` for Windows, " (2)" on collision), atomic writes, and the `job.json` manifest v1 (`media`: `audio`, `video` or `recording`); `write` removes the folder if anything fails.
- `src/asr/`: transcription. `backend.rs` reads the ggml device registry (`devices()`, via whisper-rs `raw-api`) and the pure `plans()` (dedicated GPUs by memory → CPU with `small`; the integrated GPU is left out, slower than the CPU in the 4.3 benchmark; a candidate needs its model); a GPU candidate is checked through the whisper.cpp log (`log.rs`), since a failed GPU silently falls back to CPU. `vad.rs` runs Silero itself (whisper-rs `state.full` ignores `params.vad`), loaded from memory, splices the speech and maps times back (`TimeMap::offset` adds the block start). Long audio goes in blocks of ~30 min (`Asr::blocks` changes the size; tests use seconds): the `Samples` trait reads each window (from a slice or the `Spool`), the VAD runs on it and `blocks.rs` cuts in the middle of the longest pause in its last sixth (else the last pause in the window, else a hard cut), so RAM follows the block, not the duration, and paragraphs at the seam break as in the original. `cache.rs` is `IdleCache` (unload after 10 min idle), `phantom.rs` the hallucination filter, `models.rs` embedded or `models/` models. Progress and abort use our own C trampolines (whisper-rs 0.16's "safe" ones leak, and the abort one is type-confused).
- `src/capture/` (Phase 6): live recording in two WAV tracks, `mic.wav` ("Você") and `sistema.wav` ("Outros", the output's WASAPI loopback, with silence playing on that output so the loopback never stops delivering), 32 kHz mono 16-bit, in `<data-dir>/gravacoes/<id>/` with `gravacao.json` (`storage.rs`; state `gravando`, `parada` or `transcrita` (`mark_transcribed`); `recover` finds recordings left by a crash or Ctrl+C, deletes empty and already transcribed ones and leftover `.f32`). `source.rs` holds the `AudioSource` trait (`devices`, `now_ns` on the packets' clock, `open` per track with an `Events` sender carrying a generation number) and the SPSC rings (`rtrb`, 10 s) the callbacks only copy into. `wasapi.rs` is `CpalSource` (cpal 0.18: f32/i16/i32 streams, capture timestamp = QPC of the first frame, Bluetooth from cpal's `InterfaceType` or the endpoint's `DEVPKEY_Device_EnumeratorName` starting with `BTH`). `align.rs` is pure: downmix, i16, RMS level, and the `Aligner` that pins each track to the clock (`(t − t0) × 32000`): a gap over 8 ms becomes silence at once, drift between 2 and 8 ms is corrected over 5 s by `swr_set_compensation` (`media::Resampler`, FFI on swr), an early packet loses its start. `writer.rs` is the `scriba-gravacao` thread that owns the streams: drains the rings every 20 ms, resamples to 32 kHz, writes with `hound` (`flush` every 5 s), publishes levels and "mic silent for 10 s", reopens a track on `Invalidated` (default device changed), ends on `Lost`, disk below 512 MB or the 12 h cap, and pads both tracks to the same end (not after a full disk). It keeps Windows from idle-sleeping while recording; after a suspension anyway, a gap over 30 s takes the suspended time out of both tracks (`Aligner::skip`, the recording goes on, `Status::Recording.suspended`), and a timestamp over 1 s in the future re-anchors only its own track; `TrackStats` (startup latency, filled gaps, max error, drift span, lost packets) go into the `Recording`. `mod.rs` is the `Recorder` (one recording at a time, `start`/`stop`/`status`/`finish_on_exit`, `on_finish` gets every finished recording but the Ctrl+C one). `fake.rs` (`cfg(test)` or `test-support`) is `FakeSource`: scripted signal (tones, impulses at the same instants on both tracks, given samples), rates and channels, delivery and timestamp jitter, gaps, ppm drift, an `Invalidated`/`Lost` at a given time, and a clock that can run faster than real time; `Signal::Pulsing` is a tone whose volume rises and falls (the meters move). `ScriptedSource` (same cfg) is the `--fake-audio` source: `Script::app()` in real time (two pulsing tones, the simulated devices, one of them Bluetooth) plus the words in `<data-dir>/audio-falso.txt`, re-read on each open: `perder-mic`/`perder-saida` (the device is lost 2 s after opening), `sem-microfone`, `microfone-bloqueado`, `mic-mudo`.
- `src/clock.rs`: local time via `GetLocalTime`/`GetSystemTime`, with the UTC offset from their difference.
- `src/config.rs` (paths, `config.json`), `src/instance.rs` (`instance.json`) and `--self-test` in `src/self_test.rs`.

Templates live in `templates/`, CSS source in `ui/`, embedded files in `assets/`. Other crates: `crates/scriba-model` (models embedded via `include_bytes!`: `embedded-cpu-model` = the `small` CPU model + Silero VAD + `fala.wav`, the CI release; `embedded-model` = that plus large-v3-turbo), `crates/spikes` (the Phase 0 spikes as tests), and `xtask`. The app transcribes uploaded files and live recordings, shows the result (reader with the `transcript-speaker` label of a recording, Copy, Download, Open folder) and asks "Guardar o áudio?". `assets/app.js` holds the toast, the clipboard copy from a `<template>`, the fetch-based downloads, the `scriba-erro` toast, the `confirm-dialog` (title and button from the source's `data-confirmar-titulo`/`data-confirmar-acao`: a recording's Cancel, or Remove when it failed, is "Descartar a gravação?"; if the polling swapped the card meanwhile, the request goes from the current button with the same id), the levels `EventSource` (open while `#barra-gravacao[data-gravando]` exists) and Ctrl+Shift+R (Record/Stop on any page, `preventDefault`; the Edge does not reserve it). `base.html` sets htmx `defaultSettleDelay: 0`: with the default 20 ms, a click or Enter right after a polling swap hit a button not yet processed (the old flaky focus E2E). Document new commands here as each phase adds them.

## Environment and commands

- One-time setup, in an admin PowerShell: `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1`. It is idempotent; `-LimparVcpkg` deletes vcpkg temp files. It installs the toolchain and sets the user variables `VCPKG_ROOT=C:\dev\vcpkg`, `LIBCLANG_PATH`, and `CARGO_TARGET_DIR=C:\dev\t\scriba`. The short target dir is required: inside the repo, the whisper.cpp Vulkan build exceeds MAX_PATH.
- Static FFmpeg (once, then cached): `C:\dev\vcpkg\vcpkg.exe install --triplet x64-windows-static-release --x-install-root=vcpkg_installed`. The triplet is the release-only overlay in `triplets/` (declared in `vcpkg.json`); debug libs were never linked. In manifest mode, installing another triplet replaces `vcpkg_installed/`, so an environment from before Phase 3.5 reinstalls FFmpeg once with this command.
- `.cargo/config.toml` holds the build env: triplet `x64-windows-static-release`, `+crt-static`, `FFMPEG_DIR`, the whisper.cpp `GGML_*` SIMD baseline, `CMAKE_MSVC_RUNTIME_LIBRARY`, and `CMAKE_{C,CXX}_FLAGS_RELEASE`. Without those last two, the release build of whisper.cpp comes out unoptimized (`/Od`): cmake-rs strips `/O*` and overwrites the Release flags under the Visual Studio generator. Changing `GGML_*`/`CMAKE_*` needs `cargo clean -p whisper-rs-sys` (plus `--release` for the release profile), because the build script does not track them; `release.yml` does this clean before building.
- `cargo xtask model` downloads the models to `models/` and checks SHA-256; `--only` takes comma-separated name fragments (`--only base` is what CI uses; `--only small` fetches the CPU-model candidate). `cargo xtask fixtures` regenerates `tests/fixtures/`; `--only` takes comma-separated file names (e.g. `--only fala.mkv,pausas.wav`) and reuses the existing `fala.wav`, so new fixtures never change the current ones. The recording tracks (32 kHz mono 16-bit, Maria's phrases alternating "Outros"/"Você"; `voce-com-eco.wav` adds "Outros" at −12 dB, 60 ms later) come from `--only voce.wav,outros.wav,voce-com-eco.wav` (the echo reads the other two). It needs the "Microsoft Maria" SAPI voice and the `ffmpeg` CLI.
- Lint: `cargo fmt --all --check` and `cargo clippy --workspace --all-targets --features "spikes/vulkan scriba/test-support" -- -D warnings`.
- Tests: `cargo nextest run --workspace --features "spikes/vulkan scriba/test-support"` (`tests/upload.rs` has `required-features = ["test-support"]`). Prefer nextest over `cargo test` for the whole workspace: it runs the whisper binaries one test at a time (`.config/nextest.toml`), while `cargo test` runs a binary's whisper tests in parallel and their busy-waiting threads can stall for tens of minutes; with `cargo test`, pass `-- --test-threads=1` to those binaries. Hardware tests (GPU, NVENC, real audio devices, large model) are `#[ignore = "hardware"]`; run them locally with `cargo test -p spikes --features vulkan -- --ignored`. - Releases: push a tag `vX.Y.Z` matching the `scriba` version in `Cargo.toml`; `.github/workflows/release.yml` builds, smoke-tests, and publishes exe + SHA-256 + `THIRD_PARTY_LICENSES.html` (`cargo about`). Without a tag (PRs touching the release files, or `gh workflow run release.yml --ref <branch>` once the trigger is on `main`) it builds and smoke-tests without publishing. The `setup-native` action takes `models:` (the `--only` list; `base,silero` by default, `small,silero` in the release).
- Run the app: `cargo run` opens the browser on `http://127.0.0.1:47800/?t=<token>` (the token becomes an `HttpOnly; SameSite=Strict` cookie). Flags: `--no-open`, `--port` (falls back to a free port if busy; `0` = any), `--data-dir` (default `%LOCALAPPDATA%\Scriba`), `--output-dir` (default `Documentos\Scriba`), and `--fake-pipeline` / `--fake-audio` (only with the `test-support` feature; `--fake-audio` records the `ScriptedSource` tones instead of the mic and the PC sound). A second run finds the live instance via `<data-dir>/instance.json` + `/health`, prints its URL and exits. Ctrl+C shuts down cleanly.
- CSS: `cargo xtask css` regenerates `ui/tokens.css` from the `DESIGN-scriba.md` YAML (fails if any component text/background pair is below WCAG AA) and compiles `assets/app.css` with the pinned Tailwind CLI (downloaded to `$CARGO_TARGET_DIR/tools`). Both outputs are committed; run it after changing tokens, `ui/app.css` or template classes. CI runs `cargo xtask css --check`.
- E2E: `cargo build --features test-support && cd e2e && npm ci && npx playwright test`. The `scriba` fixture in `e2e/fixtures.ts` starts a fresh debug `scriba.exe --fake-pipeline --fake-audio` per test (from `CARGO_TARGET_DIR`, or `SCRIBA_EXE`; port 0, temp data dir, `outputDir` exposed, plus `opened`/`revealed`/`asked` read from stdout, `saveAs` for the next dialog answer, `uploads`, `audioScript` for `audio-falso.txt`, and `restart()`, which kills the exe (TerminateProcess) and opens another on the same data dir; `e2e/tests/gravacao.spec.ts` covers recording), driven in the installed Edge (`channel: "msedge"`). Visual comparisons run only in CI; references live in `e2e/tests/*-snapshots/` and are regenerated by the manual `e2e-snapshots.yml` workflow (`gh workflow run e2e-snapshots.yml --ref <branch>`, then download the artifact and commit it).
- Spike D binary: `cargo build --release -p spikes --features "vulkan embedded-model" --bin exe_unico` (since 4.6 `embedded-model` also embeds the `small`, ~190 MB more).

- `ROADMAP.md` (pt-BR) is the project plan. It covers:
  - product decisions;
  - the target architecture: a Rust monolith shipped as a single Windows `.exe`, with an Axum + HTMX UI embedded in the binary, whisper-rs for transcription, ffmpeg-next for media, and cpal for microphone + system-audio loopback capture;
  - phases 0–7 with checklists;
  - the testing policy, risks, and a decision log.
- `DESIGN-scriba.md` is the visual design system the UI must follow (described below).

## How work proceeds

- One phase at a time. Start a phase only when the user asks, with its own detailed plan approved before execution, and do not roll into the next phase when it finishes.
- When a phase starts, set its row in the `ROADMAP.md` status table to "Em andamento". When it finishes, tick its checklists, set it to "Concluída", and record decisions and measured numbers in "Registro de decisões".
- A feature is done only when it has automated tests at the right level (see "Qualidade e testes" in `ROADMAP.md`) and CI is green. Tests that need real audio devices or a GPU belong in the local hardware suite, not in CI.
- If a spike or test invalidates a decision, update `ROADMAP.md` before continuing.

## Design system (`DESIGN-scriba.md`)

`DESIGN-scriba.md` is a DESIGN.md-style document in two parts:

- **YAML front matter** holds the design tokens, with English keys: `colors`, `typography`, `rounded`, `spacing`, `motion`, `elevation`, and `components`. Components reference tokens with `{group.token}` syntax, e.g. `backgroundColor: "{colors.primary}"`, and variants are separate keys (`button-primary-active`, `record-button-recording`). Phase 2 turns these tokens into CSS via `cargo xtask css`.
- **Markdown body** (pt-BR) explains the system: brand and logo, iconography, colors, typography, layout, elevation, shapes, motion, components, accessibility, microcopy, do's and don'ts, iteration guide, and known gaps.

It is the Scriba app's own design system, inspired by Apple's visual language: one blue accent for actions, pills, Inter with negative tracking, and a monochrome brand. The source logo is `docs/brand/logo-original.jpg`.

## Editing `DESIGN-scriba.md`

- Keep the front matter and the prose in sync. A token or component changed in YAML must be reflected in the body sections that describe it, and vice versa.
- Reference tokens with `{...}` rather than raw hex values in components. The body repeats hex values for readability; keep those matching the YAML.
- Follow the rules the spec sets:
  - `colors.primary` is the only action color; status colors mark state, never actions (sole exception: `button-danger` inside `confirm-dialog`).
  - Weight ladder 400/600.
  - Body text at 17px.
  - No gradients; shadows only on `toast` and `confirm-dialog`.
  - All text meets WCAG AA contrast in both themes.
  - Light and dark themes: `colors:` is the light theme, `themes.dark` overrides only differing colors. Every new color needs a dark value. Blue text uses `colors.link`; `colors.primary` is only for fills.
- Document default, pressed, focus, disabled, and error states, not hover.
- Preserve the "Lacunas conhecidas" section and update it when a gap is filled rather than deleting it silently.
